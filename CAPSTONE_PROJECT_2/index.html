Cloud-Based Tourist Flow and Attraction Analytics

An end-to-end cloud and big data analytics platform that ingests multi-source tourist telemetry, stores operational records in Oracle Database, executes scalable analytics, and forecasts crowd demand to prevent urban congestion.

⚠️ Problem Statement

  • Data Scalability: Urban tourism generates massive telemetry streams (GPS fixes, app pings, check-in logs) that swamp traditional single-node databases.
  • Geospatial Outliers: Raw telemetry is prone to coordinate drift, duplicate pings, and boundary mismatches outside registered attractions.
  • Bottlenecks & Overcrowding: Tourism authorities lack predictive foresight, causing pedestrian gridlocks, parking crunches, and safety risks.
  • Manual Resource Planning: Sanitation, transit, and security resources cannot be effectively allocated without forecasting models.

💡 Cloud & Big Data Solution

  • Decoupled Architecture: Raw data lands in Cloud Storage before distributed processing via Dataproc / PySpark clusters.
  • Operational Database: Clean application records reside in Oracle Database for relational integrity and dashboard operations.
  • Analytical Warehouse: Processed records populate Google BigQuery for low-latency SQL analytics, heatmaps, and routing analysis.
  • Machine Learning: BigQuery ML / Scikit-learn models predict crowd surges 7–14 days in advance to divert traffic to alternate sites.

Four Core Project Modules

Module 1

Data Collection & Ingestion

Ingests multi-source tourist movement data including GPS trackers, mobile travel application APIs, and manual social check-ins with batch schema validation.

Tech: GCS, REST APIs, CSV Validator
Module 2

Data Processing & Cleaning

Applies spatial coordinate bounding box filtering, removes duplicate check-ins, and aggregates telemetry via MapReduce algorithms.

Tech: Dataproc, PySpark MapReduce
Module 3

Flow & Attraction Analytics

Computes attraction popularity indices, peak visiting hours, daily visitor intensity curves, 7x4 day-slot heatmaps, and multi-hop origin-destination corridors.

Tech: Oracle SQL, BigQuery, Leaflet, Chart.js
Module 4

Prediction & Recommendation

Forecasts future visitor counts, evaluates congestion risk levels against site capacities, and recommends alternative low-density cultural destinations.

Tech: BigQuery ML / Scikit-learn

🔧 Oracle Database Setup Guide

To connect your local Oracle Database in Oracle SQL Developer:

  1. Connect as SYSTEM in SQL Developer and create dedicated schema:
    CREATE USER TOURPULSE IDENTIFIED BY your_password;
    GRANT CONNECT, RESOURCE, CREATE VIEW, UNLIMITED TABLESPACE TO TOURPULSE;
  2. Reconnect as TOURPULSE and run: database/oracle_schema.sql and database/oracle_seed.sql.
  3. Configure .env file:
    ORACLE_USER=TOURPULSE
    ORACLE_PASSWORD=your_password
    ORACLE_HOST=localhost
    ORACLE_PORT=1521
    ORACLE_SERVICE_NAME=XE
  4. Restart FastAPI server: python backend/main.py.
